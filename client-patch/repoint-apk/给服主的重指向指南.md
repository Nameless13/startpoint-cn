# 给服主的重指向指南 —— 把客户端指向你自己的服务器

面向**会跑命令、但不做逆向**的自建服部署者。跟着做完，你会得到一只
**指向你自己服务器地址、用你自己证书签名**的 WF 安卓客户端。

> 为什么需要这一步：以前发的成品 APK 里把服务器地址**写死**成了构建者的一个
> **RFC1918 内网地址**（`10.x` / `172.16~31.x` / `192.168.x.x` 这一类）。
> 不在那个网段的人装上去连不通，而且那个地址在你机器上没有任何意义。所以现在
> 不再发写死地址的成品包，改成**你自己填地址重签一只**。
> 补丁内容一个字节都不动，只换那一个地址字符串。
>
> 出厂具体是哪个值，**不用问、也不用记**：第 5.2 节的 `verify_apk_host.py`
> 不带任何参数扫一遍基座就会列出来，并按网段标注「必须替换」；
> `repoint_build.py` 也会自己找到它、把它写进构建报告的 `host_old`。
> 本文一律不写死这个值 —— 基座换一版，写死的文档就过期了。

---

## 0. 一句话原理

客户端主程序是一只 Flash/AIR 的 SWF（`assets/worldflipper_android_release.swf`），
服务器地址是其中 `pinball.config.gbits.DevConfig_gf_android` 类里的**一个字符串常量**。
`repoint_build.py` 干的事就是：解出这只 SWF → 只替换这一个字符串 → 装回 APK →
用**你的** keystore 重签 → 一路回读校验。**不重新打补丁、不改任何游戏数据。**

已实测确认（在 v2.0 发行包上）：整只包里只有两条 `IP:端口` 字符串——

| 字符串 | 所在类 | 说明 |
| --- | --- | --- |
| 出厂指向（一个 RFC1918 私有地址） | `pinball.config.gbits.DevConfig_gf_android` | 就是要被你替换掉的那条 |
| 官方开发基线残留（也落在私有网段） | `pinball.config.DevConfig_quick_start` | 官方原版包里本来就有，跟私服无关，**不用管、也不会被改** |

两条的具体值随基座版本会变，**别照抄任何文档里的数字**，直接扫你手上那只：

```bash
python -X utf8 client-patch/repoint-apk/verify_apk_host.py <你的基座>.apk
```

`①` 段会把两条都列出来、都标上「必须替换」（它们确实都在私有网段）。
你**不需要**自己分辨哪条是哪条 —— `repoint_build.py` 只在
`DevConfig_gf_android` 这一个类里找，找不到唯一一条就当场中止，
换掉的一定是第一行那条。

## 1. 你要准备的东西

| 东西 | 说明 | 哪来 |
| --- | --- | --- |
| 基座 APK | 已经打好五合一补丁的那只（免登录 / 服务器重定向 / 深渊装备门控 / 赛瑞斯双形态 / 像素占屏） | 工具仓 Release 的 `WorldFlipper-abyss-v2.apk`（约 139,714,293 字节）。作者会在 Release 说明里贴 sha256，**下载后自己核对** |

| Java 8 | 作者的构建链一直用 JDK 8 跑 FFDec；**其它版本没验证过**，想省事就用 8 | Adoptium Temurin 8 / Zulu 8。**只需要 `java` 可执行文件的路径** |
| FFDec | `ffdec.jar`，版本 26.2.1（作者验证过的版本） | JPEXS Free Flash Decompiler 的 GitHub Releases，下 nightly/zip 解出 `ffdec.jar` |
| `zipalign` | Android SDK build-tools 里 | Android SDK（`build-tools/<版本>/zipalign(.exe)`）。装 Android Studio 或单下 commandlinetools |
| `apksigner` | 同上，同一目录 | 同上（`apksigner.bat` / `apksigner`） |

| 本仓库 | `client-patch/repoint-apk/`（脚本 + 本文档） | git clone |

> 磁盘：基座 133 MiB；`--work` 里会同时躺着解出来的 SWF ×2（各 ~28 MiB）和
> APK 中间态 ×2（各 ~133 MiB），留 1 GiB 富余。
> 内存：脚本按 `-Xmx4g` 拉 FFDec，机器至少 8 GB。

## 2. 生成你自己的 keystore

**先读第 6 节再决定**——这一步定死了以后你的玩家能不能覆盖安装、存档会不会丢。

```bash
keytool -genkeypair -v \
  -keystore my-wf.keystore \
  -alias wf \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=my-wf, OU=selfhost, O=selfhost, C=CN"
```

- 它会**交互式**问你口令。**不要**用 `-storepass` / `-keypass` 在命令行里写口令
  （会进 shell 历史）。
- 问到「密钥口令（key password）」时**直接回车沿用库口令**。
  `repoint_build.py` 只给 apksigner 传 `--ks-pass`、不传 `--key-pass`，
  两个口令不一致会卡在 apksigner 要口令。
- 一个 keystore 里**只放这一把 key**。工具没有 `--ks-key-alias` 参数，
  库里有多把 key 时 apksigner 会要求你指定别名，跑不下去。
- **备份好这只 `.keystore` 文件和它的口令**。丢了 = 以后再也发不出能覆盖安装的更新，
  所有玩家都得卸载重装（见第 6 节）。

## 3. 一条完整的构建命令

### 3.1 先把口令放进环境变量（不要写进命令行）

**PowerShell**（不回显、不进 PSReadLine 历史）：

```powershell
$sec = Read-Host "keystore 口令" -AsSecureString
$env:WF_APK_KS_PASS = [Runtime.InteropServices.Marshal]::PtrToStringAuto(
    [Runtime.InteropServices.Marshal]::SecureStringToBSTR($sec))
```

**bash**：

```bash
read -rsp "keystore 口令: " WF_APK_KS_PASS && export WF_APK_KS_PASS && echo
```

> ⚠ 千万别写成 `$env:WF_APK_KS_PASS = "我的口令"`。PowerShell 会把整行存进
> `%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt`，
> bash 会存进 `~/.bash_history`，口令就明文躺在磁盘上了。
> 跑完记得清掉：PowerShell `Remove-Item Env:\WF_APK_KS_PASS`；bash `unset WF_APK_KS_PASS`。

### 3.2 跑构建

把 `203.0.113.10:8001` 换成**你自己服务器的地址**（示例用的是文档保留网段）：

```powershell
python -X utf8 client-patch/repoint-apk/repoint_build.py `
  --base    D:\wf\WorldFlipper-abyss-v2.apk `
  --host    203.0.113.10:8001 `
  --out     D:\wf\out\WorldFlipper-myserver.apk `
  --work    D:\wf\out\work `
  --ffdec   D:\tools\ffdec_26.2.1\ffdec.jar `
  --java    "C:\Program Files\Java\jdk8\bin\java.exe" `
  --zipalign  D:\Android\Sdk\build-tools\34.0.0\zipalign.exe `
  --apksigner D:\Android\Sdk\build-tools\34.0.0\apksigner.bat `
  --ks      D:\wf\my-wf.keystore `
  --ks-pass-env WF_APK_KS_PASS
```

bash 同理，把反引号换成反斜杠续行。

**10 个参数全部必填**，一个都不能省（脚本里全是 `required=True`，
没有默认值、没有 `--verbose`）。

#### `--host` 的硬限制（很重要）

脚本用这条正则校验：`\b\d{1,3}(?:\.\d{1,3}){3}:\d{2,5}\b`，而且是 `fullmatch`。所以：

- **只接受 `IPv4:端口`**。`wf.example.com:8001` 这种**域名会被直接拒绝**
  （报 `--host 不是 ip:port 形式`）。想用域名得先改脚本里的 `HOST_RE`，
  且得确认客户端那边接受主机名——**没验证过，别拿生产环境试**。
- 端口必须 2～5 位数字。
- 局域网自用填内网 IP（如 `192.168.x.x:8001`）；给外网玩家用就填**公网 IP**。
  注意这条链路是**明文 http**，没有加密，公网暴露前想清楚。
- 地址一旦烧进 APK 就固定了。你换 IP = 所有玩家都得换包。
  长期跑的话，建议先想好用一个**不会变**的地址。

## 4. 它做了什么校验、失败会怎样

`repoint_build.py` 内置校验，**任何一条不过就当场中止，`--out` 不会产生任何文件**：

1. 基座里 `pinball.config.core.DevConfig` 的 `sdkDummy:Boolean = true` 还在（①免登录没丢）；
2. 基座里 ⑤render-scale 的**三个站点全部健在**——`pixel-art`（像素占屏）、
   `member-view`（战斗队员）、`character-cell`（角色格子）。不是数关键字，
   是用打补丁时那套权威校验器逐个复核：锚点指令序列、方法头
   （maxstack/localcount/scope 深度）、伪局部变量污染；
3. `DevConfig_gf_android` 里既有的 `IP:端口` **必须唯一**，全部出现处统一替换；
4. 替换后回读：新地址在、**旧地址零残留**、①还在；
5. 三个站点**再复核一遍**，并比对重指向前后的 canonical P-code 摘要与原始 ABC
   摘要——两者都必须逐字节相同，任何一个站点被 FFDec 重序列化改动了都会中止；
6. `apksigner verify` 通过之后，才把成品挪到 `--out`，并在旁边写
   `<out同名>.build-report.json`。

> 为什么要复核三个站点：FFDec 的单类 `-replace` 会重写**整份 ABC**，
> 「我只改了一个类」不等于「别的类没被改坏」。这三个站点是像素小人显示倍率的
> 全部落点，缺一个就会出现某些界面里角色大小不对。

失败时的表现：

- 参数/环境问题 → 一行中文 `SystemExit`（如 `WF_APK_KS_PASS 未设置`）；
- 第 1、4 条不过 → `AssertionError` + 中文说明；
- 第 2、5 条不过 → `RenderScaleError`，消息里带**站点名**和摘要前后值；
- 外部工具挂了（java / zipalign / apksigner）→ `CalledProcessError`，
  **往上翻控制台**，真正的错误信息是那个工具自己打的。

> ⚠ 别用 `python -O` 跑。`-O` 会把 `assert` 全部关掉，第 1、4 条校验会**静默消失**
> （第 2、5 条抛的是真异常，`-O` 关不掉，但还是别开）。

`--work` 目录里会留下中间产物（解出来的 SWF ~28 MiB、FFDec 导出的脚本等），
脚本**不会自动清**。确认成品没问题后可以整个删掉。

## 5. 跑完怎么验证

### 5.1 看 `.build-report.json`

```json
{
  "schema_version": 2,
  "base_apk":   { "path": "...", "sha256": "..." },
  "output_apk": { "path": "...", "sha256": "..." },
  "host_old": "<基座出厂的私有地址，脚本自己读出来的>",
  "host_new": "203.0.113.10:8001",
  "host_occurrences": 1,
  "render_site_ids": ["pixel-art", "member-view", "character-cell"],
  "render_sites_before": {
    "pixel-art":      { "pcode_sha256": "<64位>", "abc_sha256": "<64位>" },
    "member-view":    { "pcode_sha256": "<64位>", "abc_sha256": "<64位>" },
    "character-cell": { "pcode_sha256": "<64位>", "abc_sha256": "<64位>" }
  },
  "render_sites_after": { "…与 before 逐字段相同…" },
  "checks": ["sdkDummy", "host_swap",
             "render:pixel-art", "render:member-view", "render:character-cell"]
}
```

要看的：

- `host_new` == 你填的地址；`host_old` == 基座原来的地址（脚本自己读出来的，
  你不用预先知道它是多少；下一节的 `--forbid` 就从这里抄）；
- `host_occurrences` ≥ 1（正常是 1）；
- `checks` 五项齐全，`render:` 三条必须都在；
- `render_sites_before` 与 `render_sites_after` **逐字段相同**（构建期已经断言过，
  不同就直接中止了，能看到这个 json 就说明过了；具体摘要值取决于基座，多少都不用管）；
- `output_apk.sha256` 记下来，发给玩家时让他们核对。

> `schema_version` 从 1 升到 2：旧版只数了 `MemberView` 里一个关键字的出现次数，
> 看不见 `character-cell` 站点。手上还有 schema 1 报告的话，那次构建没验过第三个站点。

### 5.2 只读复查：`verify_apk_host.py`

同目录下的只读脚本，**不需要 Java / FFDec**，纯 Python 标准库，只读不改：

```bash
# ① 先空扫基座：看它现在指向哪儿（带「必须替换」注解的就是出厂内网地址）
python -X utf8 client-patch/repoint-apk/verify_apk_host.py \
    D:/wf/WorldFlipper-abyss-v2.apk

# ② 再验成品：新地址在、出厂地址零残留
#    <出厂地址> 从上一条的输出、或 .build-report.json 的 host_old 抄过来
python -X utf8 client-patch/repoint-apk/verify_apk_host.py \
    D:/wf/out/WorldFlipper-myserver.apk \
    --expect 203.0.113.10:8001 \
    --forbid <出厂地址>
```

第二条的输出长这样（`<…>` 处是你实际扫到的值）：

```
① 检测到的服务器地址：
   - <官方开发基线残留的私有地址>  ×1   ← 疑似出厂/内网指向（私有或回环地址）：对别人无用，发布前必须替换成你自己的地址
   - 203.0.113.10:8001  ×1

② 旧地址残留检查：
   [OK] <出厂地址> 已清除

③ 免登录标记 sdkDummy：true
   - pinball.config.DevConfig_quick_start/iinit → true
   - pinball.config.core.DevConfig/script-init → true  ← 判定以此处为准

结论: 全部断言通过
```

退出码：`0` 全过 / `1` 有断言没过 / `2` 输入有问题（可以直接写进脚本里做门禁）。
加 `--json` 出机器可读的报告。

**它能证明什么、不能证明什么**（别夸大）：

- 能：包里有哪些 `host:端口` 字符串、其中哪些落在私有/保留网段
  （RFC1918、回环、链路本地这一类；**按网段判定，脚本里没有任何写死的地址**，
  所以基座换版本它也不会过期）、旧地址是不是真没了、
  `sdkDummy` 在 `pinball.config.core.DevConfig` 里被赋成 `true` 还是 `false`
  （读的是 `pushtrue`/`pushfalse` 指令，不是「字符串出现过」——
  `sdkDummy` 这个**名字在官方原版包里也有**，只看名字什么都证明不了）。
- 不能：证明补丁运行时真的生效。它不跑控制流分析，也不验签。
  **能不能玩，只有真机能回答。**
- 主 SWF 解析不了时会自动降级成 `--mode raw`（在所有成员的原始字节里搜 IPv4:端口），
  这时候第 ③ 项直接给 `unknown`，且可能把相邻字符串的数字粘进端口——
  脚本会标 `⚠端口可能粘连`。

### 5.3 验签

```bash
apksigner verify --verbose --print-certs D:/wf/out/WorldFlipper-myserver.apk
```

看 `Verified using v2 scheme: true`，以及证书指纹是**你自己那把**。
（构建流程里已经跑过一次 verify，这里是你自己再确认一遍。）

### 5.4 装机确认连的是你的服

```bash
adb install -r D:/wf/out/WorldFlipper-myserver.apk
adb shell am start -n com.leiting.wf/com.leiting.sdk.activity.PrivacyActivity
```

- 包名：`com.leiting.wf`；唯一带 LAUNCHER 的启动 Activity：
  `com.leiting.sdk.activity.PrivacyActivity`（已从 AndroidManifest 实测确认）。
  （模拟器上直接点桌面图标也行；`monkey -p com.leiting.wf -c android.intent.category.LAUNCHER 1`
  在 MuMuManager sh 通道下参数会被拆坏，所以这里给的是 `am start -n` 显式写法。）
- **最可靠的确认方式是看服务端日志**：客户端一起来就会连着打一串请求
  （版本检查 `/shijtswy/version/client_release_android.dis`、登录、加载存档 `/load` …），
  服务端控制台立刻有访问记录 —— 有记录 = 连上了你的服。
- 进游戏后能看到你自己服的存档/角色，就是通了。
- 卡在启动/连接超时 = 没连上，翻第 8 节。

## 6. ⚠ 证书与存档：这一节决定你以后能不能平滑更新

**Android 的规矩：同包名的应用，只有签名证书相同才能覆盖安装。**

| 情况 | 玩家要做什么 | 后果 |
| --- | --- | --- |
| **一直用同一把 keystore** | 直接覆盖安装新包 | 本地身份保留，**存档不丢**，无感更新 |
| **换了 keystore**（或第一次从别人的包换到你的包） | **必须先卸载再装** | 卸载会抹掉客户端本地身份 → 玩家进去**变成新号** |

补充说明：

- 存档本体在**服务端数据库**里，没丢。丢的是客户端本地那份「我是谁」的身份标识。
  服主可以按 `device_id` 在后台把老存档重新绑到新身份上（见 self-host 指南），
  但这是**手工活**，玩家一多就是灾难。
- v1.0 → v2.0 当年就是这么回事：换了签名，所有人被迫卸载重装、变新号。
  **别再来一次。**
- 所以：**第一次签之前就把 keystore 定下来，然后备份、再备份。**
  换机器、换电脑、重装系统，都得把这只文件带走。
- 也因此，**别用作者的包直接覆盖你自己签的包**，反之亦然——证书不同，装不上去。

## 7. 服务端那边要配什么

客户端只认你填进 `--host` 的那一个地址，所以服务端必须在**那个 IP、那个端口**上能被手机访问到：

1. **监听地址**：`CN_LISTEN_HOST` 默认是 `127.0.0.1`，**只有本机能连**，手机连不上。
   要让手机连上必须设成 `0.0.0.0`。
2. **但是**：`CN_LISTEN_HOST` 一旦不是回环地址，服务端**强制要求** `CN_ADMIN_TOKEN`
   （≥32 字节的 UTF-8），否则**直接启动失败**并抛
   `CN_ADMIN_TOKEN is required for non-loopback CN_LISTEN_HOST`。
   这是保护后台管理接口的，不是 bug。生成一个长随机串填进去。
3. **端口**：`CN_LISTEN_PORT` 默认 `8001`，要和你 `--host` 里写的端口**一致**。
4. **防火墙**：Windows 防火墙默认会拦入站，给该端口放行；云服务器还要开安全组。
5. 手机和服务器要在同一网络里能互通（同一局域网 / 或服务器有公网 IP）。

自检：在**手机**的浏览器里打开 `http://<你的地址>:<端口>/`，
能出东西 = 网络通了；打不开 = 先解决网络，跟 APK 无关。

## 8. 常见坑

| 症状 | 原因 | 怎么办 |
| --- | --- | --- |
| `--host 不是 ip:port 形式` | 填了域名，或端口位数不对 | 只能填 `IPv4:端口`，端口 2～5 位 |
| `WF_APK_KS_PASS 未设置` | 环境变量没设，或换了一个新终端窗口 | 环境变量只在当前会话有效，重开窗口要重设 |
| `基座 DevConfig_gf_android 内 host 值不唯一` | 基座不是预期的那只 | 换回正确的五合一基座；别拿官方原包当基座 |
| `基座缺①免登录(sdkDummy=true)` | 基座是官方原版或别的包 | 同上 |
| apksigner 要口令 / 报多个 key | 密钥口令≠库口令，或库里有多把 key | 重新按第 2 节生成一把干净的 keystore |
| 装不上，报签名冲突 | 机器上装着**别的证书**签的同包名应用 | 先卸载旧的（**会丢本地身份，见第 6 节**） |
| 游戏起来卡在连接/一直转圈 | 地址或端口填错、服务端只听 127.0.0.1、防火墙拦了 | 按第 7 节自检；服务端日志里没有任何请求 = 根本没连上 |
| 明文 http 被系统拦截？ | **不会**。已确认基座 manifest 的 `<application>` 带 `usesCleartextTraffic=true`，明文放行由这一条保证。（包内虽有 `res/xml/lt_network_security_config.xml` 且其 `base-config` 也是 `cleartextTrafficPermitted=true`，但 `<application>` **没有** `networkSecurityConfig` 属性引用它，即该文件未接线、不参与判定。） | 无需额外配置；但也意味着流量是明文的，公网慎用 |
| 安卓版本装不上 | 基座 `minSdkVersion=21`（Android 5.0）、`targetSdkVersion=30`（Android 11） | Android 5.0 以下装不了；模拟器（MuMu 等）没问题 |
| 校验好像没跑就过了 | 用了 `python -O` | 去掉 `-O` 重跑 |

## 9. 这套东西**不做**什么

- 不重新打补丁：基座缺哪个补丁，成品就缺哪个。补丁面截止到 2026-07-18，之后没有新的客户端侧补丁。
- 不改游戏数据（角色/数值/关卡都在服务端和 CDN，跟这只 APK 无关）。
- 不改包名、版本号、图标。
- 不帮你搞证书托管、不帮你分发。签名是你自己的责任。

   本地对应文件：`out/client-detail-recovery-20260718/WorldFlipper-gerald-seris-safe-local-v2.apk`

   Release 上实际挂着的那只逐字节核对再往说明里贴）。

   > **v2.0-threechar / WorldFlipper-abyss-v2.apk 是「基座」，不是拿来直接装的成品。**
   > 它里面的服务器地址写死为构建者的一个 **RFC1918 内网地址**，
   > 你**不在那个网段就连不上**——这是预期行为，不是坏包。
   > （具体是哪个地址，用 `verify_apk_host.py` 空扫一遍就会列出来并标红，
