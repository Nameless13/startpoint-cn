# 深渊连战塔：混合属性抗性、可驱散混入与不屈龙心配对设计

日期：2026-08-05  
前置：`2026-08-05-rogue-attack-cap-high-threat`

## 目标

在保留 `元素滞钝 / 三相封界 / 元素禁壁 / 五相绝域` 四个预设的同时，新增能对每个属性独立抽强度的 `混相禁域`；让软性敌方增益按约 3:1 混入可驱散版本；并保证 `不屈龙心` 每次出现都伴随一个对普通队伍可见的非“加成”场机制。

## 混相禁域

一张逻辑卡先抽 `N=1..5` 个不重复的数据层元素码，再为每个元素独立抽一个深度允许的强度：

| 深度 | 随机强度集合 |
|---|---|
| 前 20% | `1` |
| 20%～50% | `1, 9` |
| 50%～80% | `1, 9, 99` |
| 最后 20% | `1, 9, 99, 999` |

元素码始终是数据层 `1火/2水/3雷/4风/5光/6暗`，不得写客户端内部码。文案逐元素调用 `resistance_label(r)`，不写死“免疫”，也不透露可驱散性。

工坊/测试可通过以下结构确定性给出作者原例：

```json
{
  "curses": ["混相禁域"],
  "element_mix": [
    {"element": 1, "strength": 1},
    {"element": 2, "strength": 999},
    {"element": 3, "strength": 999},
    {"element": 6, "strength": 999}
  ]
}
```

这必须生成“火减半 + 水雷暗降至 0.1% + 风光完全不受影响”。forced 表必须是 1～5 项、元素唯一且为 1～6、强度只允许 `1/9/99/999`；非法输入响亮失败，不消耗混合卡自身的随机抽签。

## 可解性

`curse_conflict()` 在所有诅咒合并后同时执行两层判据：

1. 任意正属性抗性影响到的属性集合必须少于 6，保证至少一个属性完全不受影响。
2. `r>=99` 的高阻断属性集合必须少于 6；完全免疫的四伤害类型集合必须少于 4。

多张卡分别覆盖一部分时也必须合并判定，拒绝时 `log()` 记录并重抽。注释要说明定值/比例伤害绕过属性抗性，因此这是普通属性伤害路径的产品闸，不宣称机制上绝对无解。

## 可驱散性模型

规范化原子采用：

```python
(target_or_constructor, strength, cancelable)
```

旧二元/三元调用兼容为 `cancelable=False`。一张逻辑软卡只抽一次 `rng.randrange(4) == 0`，得到约 25% 可驱散；禁止逐属性、逐叠层抽签，避免多属性/90 层卡扭曲比例。

硬约束：

- 属性 `r>=99` 永远 `cancelable=False`。
- 伤害类型 `r>=1` 永远 `cancelable=False`。
- `层叠龙鳞`、`不屈龙心` 维持不可驱散。
- 同一混合卡含软硬原子时，硬原子进 false 组；软原子共享卡级抽签。

`CreateCondition.params[4]` 是整条命令共用的布尔，因此 `build_immunity_dsl_tree()` 必须把一次性原子按 bool 分成至多两条命令：先不可驱散组，再可驱散组。`immunity_program()` 的稳定签名必须包含 bool，避免数值相同但可驱散性不同的程序错误复用。文案绝不标 `[可驱散]`。

3:1 指“有资格随机化的软逻辑卡”的长期采样比例；硬墙不拿来凑比例。第 4 批最终报告再对整塔敌方增益做总体统计。

## 不屈龙心

数值不再上调，继续沿用 `ACToleranceOfDebuff strength=1` 与可见 `20/50/90` 层。客户端常规判据是 `hitRate - debuffResistance`；`forceApply=true` 绕过。文案统一为：

```text
减益耐性×N层（普通减益几乎无法命中；强制赋予除外）
```

在 `abyss_curses.finalize()` 第一次冲突检查之前执行配对补全，按 `stacked_resistance` 中的 `ACToleranceOfDebuff` 识别，不依赖显示名：

- 已有 `cat != "加成"` 的安全 field：不新增。
- 只有“加成”field：原位替换其中一个为未占用的非加成安全 field。
- 没有 field：追加恰好一个非加成安全 field；不占普通诅咒名额，并把有效 `field_requested` 至少记为 1。
- 无 general_boss 载体或非加成候选耗尽：明确失败；正常抽取路径应记录拒绝并重抽。

补全后再跑统一 `conflict()` 和 `apply_picks()`，使 random/combo/forced 三条路径共享同一保证。

## 验收

- 可确定性产出作者四属性混合例；4、5 完全缺席。
- 随机混合每张 1～5 个唯一属性、强度逐属性独立且受深度限制。
- 跨卡合并后永远留至少一个完全不受影响属性和一种伤害类型。
- c36、autoHighLevel、general_boss 载体门禁对混相卡与旧预设同样生效。
- DSL false/true 分组、参数形状、AMF3/raw-deflate 往返及程序签名均有测试。
- 软卡固定 seed 采样可驱散比例接近 25%，硬墙与龙心全部 false。
- 不屈龙心保留 20/50/90 层，文案不再出现“百分点”，且最终必有非加成可见领域。
- 全量精确 `337 tests / failures=7 / errors=30`。

## 边界

不写 store、不发布、不改 `assets/`、`sync_pending.json` 或 `wf_dev_catalog.py`，不推设备。本批不扩 GUI schema；`element_mix` 是生成器/计划 JSON 接口，GUI 若未携带该字段则使用随机混相卡，不静默伪造固定原例。
