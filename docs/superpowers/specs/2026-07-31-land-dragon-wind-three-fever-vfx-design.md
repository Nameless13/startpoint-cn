# 风巨蜥三类 Fever 首领技与 PF 演出修复规格

日期：2026-07-31  
角色：风巨蜥（`land_dragon_wind_playable`，ID `149998`）  
目标包：`work/character_packs/land_dragon_wind_poc`  
下一候选版本：`1.1.9`  
状态：交互设计已由用户确认；等待书面规格复核后实施  
交付边界：允许 workspace-only 构建、完整预检和可恢复 MuMu 装机；不发布 CDN、不修改存档或活动资源

## 1. 已确认目标

1. Fever 技能由现有五个随机分支合并为三个辨识度明确的首领技：
   - 爪子重击；
   - 超大激光炮；
   - 全屏旋风。
2. 三类使用完全相同的正权重，归一化抽取概率均为 `1/3`。
3. 三类满级名义总倍率均为约 `80×`，不得因演出层数不同造成倍率偏差。
4. 原有技能特效全部明确归入三个分支，避免随机到某一分支时被误认为资源丢失。
5. PF2 恢复为从命中点完整扩散至全屏的绿色波环，并在可见扩散拍点结算技能伤害。
6. PF3 继续使用“小激光”定位，但必须比 `1.1.8` 清晰、宽大；Fever 激光必须与之形成
   明显的超大尺寸差。
7. 所有层状风波统一朝玩家发射方向／屏幕上方推进，不得再次朝下。

## 2. 当前问题与根因

### 2.1 PF2 只闪出一小圈

`wind_ring` 原始时间线共有 263 帧，当前 PF2 却在第 36 帧强制结束。设备只能看到扩散早期
的小圈，永远播放不到覆盖全屏的后半段。

修复不直接恢复 263 帧慢速播放，而是保留完整 1–263 帧视觉变化，将它重新计时到约 90 帧。
这样既能看到完整扩散，又不会恢复成缓慢拖沓的旧手感。

### 2.2 PF3 和 Fever 激光都太小

两者共用原版 `laser` 像素链，源纹理约为 123×502。当前 PF3 缩放仅 `0.9×`，Fever
缩放仅 `2.25×`，设备上都没有形成预期的炮击体量。

本轮将两者继续保持独立呈现参数：

- PF3：约 `1.75×`，作为清晰可辨的中小型激光；
- Fever：约 `4.5×`，作为跨越主要战场区域的超大激光炮。

实际最终值允许在一次真机尺寸校正中微调，但 Fever 宽度和长度必须显著大于 PF3。

### 2.3 风波再次向下

当前全屏风暴分支的三层 `wave_arc120` 使用 `rotation=0`；旧静态测试错误地把该参数写成
“向上”。设备结果证明它实际向下。玩家侧已正常向上的其他风波使用 `rotation=π`，因此
本轮统一改为 `π`，并把方向列入真机强制验收，而不是只依赖 DSL 断言。

### 2.4 部分技能像是没有特效

当前五个随机分支分别只装载一部分效果。玩家连续抽到不同分支时，会把没有出现在本次分支
中的效果理解为“丢失”。本轮将效果资源固定归档到三个复合演出，每类内部不再二次随机。

## 3. 三类 Fever 首领技

技能发动时只抽取一个分支。三类使用相同权重；不得采用 `33/33/34` 之类有偏分配。

### 3.1 爪子重击

效果分配：

- `target_sight`：锁定最近敌人；
- `slash`：两道交叉斩作为蓄势；
- `craw`：放大后的巨爪作为最终重击。

演出节奏：

1. 最近敌人处出现锁定标记；
2. 两道交叉风斩先后出现，明确指向命中位置；
3. 巨爪延长至约 54–60 帧，不再闪一下消失；
4. 巨爪完全张开时结算一次重击。

伤害合同：

- 锁定与交叉斩为辅助演出，不重复堆叠大量伤害数字；
- 最终巨爪为 1 个真实玩家侧技能攻击事件；
- 满级名义倍率 `80×`。

### 3.2 超大激光炮

效果分配：

- `wave_arc30`：炮口前的聚风和蓄力风压；
- `laser`：完整开始、循环和收束阶段的超大光束。

演出节奏：

1. 角色面向最近敌人／玩家发射方向完成聚风；
2. 超大激光展开至约 `4.5×`；
3. 光束维持足够时间，随后播放收束，不得中途裁掉；
4. 所有风压和判定沿同一向上轴线推进。

伤害合同：

- 8 个真实玩家侧技能攻击事件；
- 满级每段约 `10×`；
- 满级名义总倍率 `80×`；
- 判定宽度和长度随视觉同步扩大，不能出现“画面很大但只打中中心细线”。

### 3.3 全屏旋风

效果分配：

- `overall`：全屏旋风主体；
- `wave_arc120_fast`、`wave_arc120_middle`、`wave_arc120_slow`：三层速度不同的上行风浪。

演出节奏：

1. 全屏风场先形成；
2. 三层风浪按紧凑间隔向上穿过战场；
3. 主体和风浪保持可读，不得同帧全白后立即消失；
4. 三层风浪全部使用已由设备反馈确认的上行方向。

伤害合同：

- 8 个真实玩家侧技能攻击事件；
- 满级每段约 `10×`；
- 满级名义总倍率 `80×`；
- 使用全屏／大范围玩家侧判定，但每个判定区对同一敌人单拍最多命中一次。

## 4. PF2：完整扩散技能伤害波环

触发合同保持不变：

- 仅在 PF2 首次真实命中敌人时触发；
- 同一次 PF 的后续命中不得重复生成整套波环；
- 不在弹起瞬间提前播放。

演出与伤害：

- 完整使用 `wind_ring` 的 1–263 帧内容；
- 重计时到约 90 帧，连续播放至全屏扩散完成；
- 固定在首次碰撞位置，不缓慢漂向场外；
- 在三个可见扩散阶段生成由小到大的技能判定区；
- 三拍满级倍率合计 `12×`，建议为 `4× + 4× + 4×`；
- 原 PF2 的 12 个真实强化弹射攻击事件及其总倍率保持不变。

PF2 的追加波环伤害继续按技能伤害结算；原 PF 本体仍按强化弹射伤害结算。

## 5. PF3：可读的小型激光

触发合同保持不变：

- 仅在 PF3 首次真实命中敌人时触发；
- 同一次 PF 只触发一束；
- 不在弹起瞬间提前播放。

演出与伤害：

- 复用完整 `laser` 像素链；
- 缩放由 `0.9×` 提升到约 `1.75×`；
- 保留完整炮口、主体和收束，不能只闪出一道细线；
- 四个可见伤害拍点，满级总倍率保持 `24×`；
- 原 PF3 的 24 个真实强化弹射攻击事件及其总倍率保持不变。

PF3 激光必须明显小于 Fever 的 `4.5×` 超大激光，但在手机屏幕上仍能一眼看清。

## 6. 资源与数据约束

- 三个 Fever 分支均只使用玩家侧 `ShowEffect`、`CreateHitArea` 和
  `CreateNormalAttack` 等已验证生命周期。
- 不运行敌方 AI，不使用 `SpawnFunnel` 或敌方 `CreateTargetAttack`。
- 所有效果继续位于角色独占资源路径，像素、atlas、parts 和 timeline 引用必须闭包完整。
- 保留角色完整 Pixel 攻击链；技能结束后必须释放控制，角色能立即继续移动和施放技能。
- 不修改全局 PF 类型或其他角色的标准 PF 资源。

## 7. TDD 与静态验收

实施时先让新合同在 `1.1.8` 上失败，再修改构建器。测试至少锁定：

1. Fever 概率块恰好有三个分支，三者权重相同且均为正数。
2. 三分支满级倍率分别为 `80× / 80× / 80×`。
3. 爪子分支包含 `target_sight + slash + craw`，巨爪只有一个最终伤害事件。
4. 激光分支包含 `wave_arc30 + laser`，激光约 `4.5×`、8 段、总计 `80×`。
5. 风暴分支包含 `overall + 三种 wave_arc120`，8 段、总计 `80×`。
6. 三种 `wave_arc120` 全部使用上行方向配置。
7. PF2 时间线完整映射原 263 帧，并压缩到约 90 帧；存在三拍扩散技能伤害，总计 `12×`。
8. PF3 激光约 `1.75×`、四拍、总计 `24×`。
9. PF2／PF3 仍由命中事件触发，AbilitySkill 顶层执行者继续使用已修复的玩家执行者引用，
   防止 C16103 回归。
10. 角色技能和 PF DSL 无 `SpawnFunnel`、敌方目标生命周期、未注册字符串或非法哨兵。

整包还必须通过：

- 角色专项测试；
- 37/37 生产必需资产；
- Master／DSL／纹理引用零缺失；
- manifest/hash/seal 完整；
- 三层一致、无输入漂移；
- `release_ready=true`、`can_prepare=true`、`writes_live=false`。

## 8. MuMu 真机验收

自动预检通过后，使用新的隔离暂存目录可恢复地安装到当前 MuMu 实例，并检查：

1. PF2 只在命中时触发，能看见从碰撞点扩散到全屏的完整绿圈，三拍伤害与圈径同步。
2. PF3 是清晰的中小激光，明显大于旧 `0.9×` 版本，但小于 Fever 超大激光。
3. Fever 三类均能被抽到，抽取频率没有可见固定偏向。
4. 爪子锁定、交叉斩和巨爪完整出现，巨爪不再闪得看不清。
5. 超大激光覆盖主要战场区域，完整播放开始、持续和收束，实际为 8 段。
6. 全屏旋风主体和三层风浪均可见，风浪全部向上，实际为 8 段。
7. 三类在固定训练目标上的满级裸倍率总计均约 `80×`。
8. 放完技能后角色立即恢复可操作；连续 PF、技能和 Fever 不崩溃。
9. 日志无 C16103、C7101、G3000、C8601、F1009、Fatal 或 ANR。
