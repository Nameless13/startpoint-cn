# 深渊征服者：全队独立三次生存强化设计

日期：2026-08-05
装备：`8000113` 深渊·征服者

## 用户裁定

- 三名主位队员各自拥有 3 次不死，不共享次数。
- 三名主位队员各自拥有 3 次低血无敌触发次数，不共享次数。
- 低血无敌只赋予越过阈值的那名队员，不因一人低血而给全队无敌。
- 沿用现有 1% 阈值、10 秒持续时间和不可驱散属性。

## 数据设计

只调整 `wf_rogue_rewards.py` 中 `8000113` 的前两个 `EffectSpec`，不新增效果槽。

### 槽 1：全队三次不死

沿用官方 `ability_soul[300001]#5` 的 `ConditionGuts` 行，并输出：

| 列 | 值 | 含义 |
|---|---:|---|
| `c44` | `468` | `ConditionGuts` |
| `c45` | `5` | `Party`，三名主位全体 |
| `c46` | `(None)` | 不限属性 |
| `c48/c49` | `100000` | 100% 不死概率，不放大成 300% |
| `c56/c57` | `300000` | 每名目标 3 次 |
| `c64` | `1` | 不可驱散 |
| `c69` | `false` | 保留官方值 |
| `c71` | `1` | 保留官方初始倍率 |

客户端 `Party` 路径会遍历三名主位，并在每名目标上按 `number=3` 创建三个独立 Guts 条件。因此单个征服者能力来源的结果是每人 3 次，而不是三人共享 3 次。

### 槽 2：每名队员独立三次低血无敌

沿用官方 `ability_soul[300002]#6` 的 `ConditionInvincible` 内容，并输出：

| 列 | 值 | 含义 |
|---|---:|---|
| `c24` | `25` | `HpLow` 触发 |
| `c25` | `5` | `OneOfParty`，为每名主位建立监听器 |
| `c26` | `(None)` | 不限属性 |
| `c27/c28` | `1000` | 生命值不高于 1% |
| `c31` | `3` | 每个监听器最多触发 3 次 |
| `c32` | `0` | 无冷却，保留既有值 |
| `c44` | `16` | `ConditionInvincible` |
| `c45` | `7` | `TriggerPuller`，只作用于越线者 |
| `c46` | 空串 | 触发者目标不使用内容目标组 |
| `c54/c55` | `60000000` | 10 秒，保持不变 |
| `c56/c57` | `100000` | 每次赋予一个无敌状态，不误改成三层 |
| `c64` | `1` | 不可驱散 |
| `c69` | `false` | 保留官方值；不承担次数隔离语义 |

客户端对 `OneOfParty + HpLow` 为每名主位创建独立 `AbilityTriggerHandler`；每个 handler 各自持有 `trigger_limit=3`，所以一名队员触发不会消耗其他队员次数。

阈值监听是“从阈值外进入阈值内”事件：队员一直停留在 1% 以下时不会每隔 10 秒自动续无敌。下一次触发通常需要先恢复到 1% 以上，再次降到不高于 1%。

## 模板与风险边界

- `HpLow + OneOfParty + TriggerPuller` 有官方同形模板，且官方存在大于 1 的触发上限。
- `ConditionGuts + Party` 没有一条官方完全同构行；它由官方 Guts 行、官方 Party 目标行和客户端明确执行分支组合而成，静态合法性校验已通过，但仍标记为黄灯，必须真机战斗验证。
- `ability_soul[8000113]` 同时服务武器本体及同键魂珠。多个来源会建立冗余但独立的 handler/条件，不过同一次跨阈值会让所有低血 handler 同帧触发并同步扣次，Guts 消耗也会同时扣除所有 Guts 条件；正常实战仍是 3 个生存周期，不会自然串成 6/9 次或 20/30 秒。客户端没有兼容“每人独立监听”且跨来源全局去重的通用字段，本次保留官方执行路径并把重复来源列入真机观察项。

## 生成文案

数据层描述预期包含：

```text
赋予全队 状态Guts 100%×3次[不可驱散]
HP≤1%(限3次) → 赋予触发者 状态无敌(10秒)×1次[不可驱散]
```

真机本地化可使用更自然的等价措辞，但数值、目标与次数必须一致。
